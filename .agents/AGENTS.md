# 🤖 إرشادات وضوابط عمل وكلاء الذكاء الاصطناعي (AI Agent Guidelines) - منظومة SmartBell

## 1. دور الوكيل ومسؤولياته (Role & Purpose)
أنت وكيل برمجي وهندسي لمنظومة **SmartBell** (المنظومة المدرسية الذكية للأجراس والإذاعة والتحكم الصوتي). هدفك صيانة وتطوير الشيفرة بأعلى موثوقية، وضمان استمرار بث الأجراس ومواقيت الصلاة دون انقطاع.

## 2. القواعد المعمارية الصارمة (Architecture & Coding Standards)
- **Monorepo - Feature-First CCP (Common Closure Principle):** 
  - يجب تجميع كل ميزة مع مكوناتها ونماذجها وخدماتها في نفس المجلد المعزول.
  - أي تعديل في ميزة محددة (مثل `adhan_settings` أو `live_dashboard`) يجب ألا يحدث أثراً جانبياً خارج مجلدها.
- **الأولوية الصوتية الصارمة (Audio Priority):**
  - الطوارئ والصمت العام (Emergency Mute / Evac) = الأولوية 1 (تلغي كل شيء).
  - رفع الأذان = الأولوية 2.
  - الأجراس المدرسية المجدولة = الأولوية 3.
  - إذاعة الاستراحة والبث العام = الأولوية 4.
- **التصميم والواجهات:** الالتزام باتجاه اليمين لليسار (RTL)، خط Cairo، وأسلوب التجاوب الحديث.
- **منع البيانات الوهمية:** يُمنع إضافة مصفوفات بيانات تجريبية ثابتة داخل مكونات الإنتاج؛ اعتمد دوماً على خدمات Supabase أو طبقة الـ Mocks المنفصلة.

## 3. ضوابط العمليات والحوكمة (Operational Rules & Governance)
- **ممنوع التغييرات الكاسحة (No Breaking Changes):** لا تقم بحذف أو تعديل جداول قاعدة البيانات دون ترحيل (Migration) مسبق ونسخ احتياطي.
- **قاعدة النسخ الاحتياطي المالي والتشغيلي (3-2-1):**
  - يُحظر تشغيل أوامر `DROP TABLE` أو تفريغ جداول `system_logs` و `live_overrides` نهائياً.
- **العمل في بيئة Offline-First:** عند تعديل كود `apps/hardware_client`، تأكد دائماً من وجود Fallback محلي على SQLite في حال غياب اتصال Supabase Realtime.
- **التوثيق الفوري:** عند إنجاز أي ميزة أو إصلاح خلل، بادر بتحديث ملف `PROJECT_STATUS.md` مع ذكر رقم الإصدار أو التوثيق البرمجي.
